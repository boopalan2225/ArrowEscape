# Baseline profile - classes and methods to compile AHEAD of first run.
#
# WHY THIS FILE EXISTS
# Without it, everything here is interpreted the first time it runs and only
# gets JIT-compiled once the player has already waited. That is exactly the
# shape of the complaint this file answers: "the first launch is slow, after
# that it's fine." Level generation is the worst offender - a hill-climb of
# up to four thousand solver sweeps, running interpreted, on the one screen
# the player is staring at.
#
# FORMAT
#   L<class>;                       - load this class eagerly
#   HSPL<class>;->method(sig)ret    - H=hot, S=startup, P=post-startup
#   ** wildcards match any method/signature, which is what lets this file
#   stay readable instead of listing a thousand signatures that rot on the
#   next refactor.
#
# This is hand-written on purpose. A generated profile is better and needs a
# device + the androidx.benchmark baseline profile module to produce; when
# that exists, regenerate and replace this wholesale rather than editing it.
